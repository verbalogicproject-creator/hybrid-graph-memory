# Case Study: Topological Multi-Agent Orchestration

## The Problem with Standard RAG
When a user asks a complex architectural question (e.g., *"How does the CLI talk to the database?"*), a standard vector database performs a k-NN search. As mathematically proven by our evaluation harness, in high-dimensional space this collapses into "hubness"—pulling in a massive, noisy hairball of highly-connected but unrelated code across the entire project. The LLM's context window fills with noise, leading to hallucination and context degradation.

## The Topological Solution
Instead of forcing a single LLM to read a noisy hairball, the Antigravity Memory OS leverages the mathematical primitives of graph topology and multi-agent systems.

### Pipeline Execution Log

**1. The Query**
*User:* "How does the CLI interactive menu handle the System 2 Worker command?"

**2. The Semantic Router (Step 1)**
The engine performs a vector search *only* to find the geometric entry points into the graph. It finds nodes like `runDashboard`, `commander`, and `ultra_bridge.py`.
The router consults the `multi_agent_communities.json` map (generated by the background ULTRA System 2 worker) and determines:
> *Routing Reason:* Query hits `[runDashboard]` -> Routing to `community_0` (The CLI)
> *Routing Reason:* Query hits `[ultra_bridge.py]` -> Routing to `community_2` (The Python Engine)

**3. Sub-Graph Checkout (Step 2)**
Instead of passing everything to one model, the orchestrator opens parallel threads.
* **Edge Agent A** is spawned. It is handed *only* the nodes from `community_0`. Its system prompt strictly isolates its reasoning to the CLI boundary.
* **Edge Agent B** is spawned. It is handed *only* the nodes from `community_2`. Its system prompt strictly isolates its reasoning to the Python execution boundary.

*Because the context is mathematically isolated, the LLMs run faster, use fewer tokens, and suffer zero quantization deformation.*

**4. The Synthesizer (Step 3)**
The Edge Agents return their isolated insights:
> *Agent A Insight:* "The CLI uses an interactive prompts menu. When 'system2' is selected, it uses child_process.spawnSync."
> *Agent B Insight:* "The Python script ultra_bridge.py requires a --db argument and performs Louvain clustering."

The Synthesizer Agent receives these reports and merges them into the final, cohesive answer for the user:
> *"When you select the System 2 Worker from the CLI menu, the TypeScript engine uses `spawnSync` to execute `ultra_bridge.py`, passing the current SQLite database path as the `--db` argument so the Python script can perform Louvain clustering."*

## The Falsifiable Result
By using graph topology (Louvain community detection on FP16 SQLite edges) to route prompts to parallel agents, we achieve:
1. **Zero Hallucination:** Agents cannot hallucinate about the database if they are only given the CLI community.
2. **Infinite Scale:** A 1-million node codebase can be reasoned about accurately without exceeding a standard 8k context window, because the graph is dynamically fractured and assigned to micro-agents.
