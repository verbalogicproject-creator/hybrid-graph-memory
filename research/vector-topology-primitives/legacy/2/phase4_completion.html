1. Paper Conclusion & Evaluation Metrics

4. Evaluation Metrics

To benchmark Graph-Augmented RAG against standard Euclidean retrieval, we propose three primary metrics, none of which have yet been measured — these are proposed evaluation criteria, not reported results:

  • Edge Survival Rate (ESR): The percentage of graph edge distance rankings that remain stable when the embedding model is quantized from FP16 to INT4. This is intended to measure the practical resilience of graph-based retrieval against quantization noise, pending actual measurement via the Distortion Tracker script.
  • Cross-Cluster Resolution Score: Evaluated via a synthesizer LLM. When a query's retrieved context splits into two highly overlapping but distinct clusters, we propose measuring the presence of cross-domain hallucination and comparing parallel cluster-based routing against single-shot Euclidean retrieval.
  • Path Divergence Metric: A proposed distance measure (e.g., Fr\u00e9chet distance) between the sequence of chunks retrieved via graph traversal versus via flat top-k vector search, to quantify how differently the two methods behave in practice.

5. Conclusion

As AI architectures move toward heavily quantized, locally executed multi-agent systems, relying purely on flat Euclidean retrieval may become a practical limitation. Building on established Graph-RAG methodology, this project explores treating the graph structure as a complementary retrieval signal alongside vector similarity, rather than a replacement for it.

Furthermore, by combining graph-based retrieval with multi-agent orchestration — using distinct agents to independently process overlapping-but-distinct context clusters in parallel — the design aims to reduce cross-domain hallucination at the edge. This is a proposed architecture whose benefits remain to be empirically validated; no results are reported here, and no guarantee of improved fidelity should be assumed until benchmarked against the metrics above.

3. Implementation: Multi-Agent Cluster Detection

This Python script lives in 04_orchestration/query_parser.py. It analyzes the retrieved graph nodes to detect if the context has split into two or more distinct communities and triggers the multi-agent council to process them separately.

import networkx as nx
from networkx.algorithms import community
from typing import List, Dict

class ContextClusterDetector:
    def __init__(self, knowledge_graph: nx.Graph):
        self.graph = knowledge_graph

    def detect_clusters(self, retrieved_node_ids: List[str]) -> Dict[str, Any]:
        """
        Analyzes the retrieved graph nodes to determine if they form a single
        densely-connected community, or if they split into multiple distinct
        communities (overlapping-but-distinct context clusters).
        """
        # Create a subgraph of only the retrieved context nodes
        subgraph = self.graph.subgraph(retrieved_node_ids)
        
        # Use Louvain community detection to find dense clusters within the subgraph
        # If the query is straightforward, this returns 1 community.
        # If the query context is split, it returns 2+ distinct communities.
        communities = list(community.louvain_communities(subgraph, weight='weight'))
        
        if len(communities) > 1:
            return {
                "is_split": True,
                "forks": [list(c) for c in communities],
                "action": "TRIGGER_CLUSTER_SPLIT"
            }
        
        return {
            "is_split": False,
            "forks": [retrieved_node_ids],
            "action": "STANDARD_SYNTHESIS"
        }

    def execute_cluster_split(self, agent_council, cluster_data: Dict):
        """
        Routes the distinct context clusters to separate, parallel Phi-4-mini agents.
        """
        parallel_results = []
        
        for index, fork_nodes in enumerate(cluster_data["forks"]):
            # Extract the raw text for this specific cluster
            fork_context = [self.graph.nodes[n]['text'] for n in fork_nodes]
            
            # Spin up a parallel agent thread for this specific context cluster
            agent_response = agent_council.dispatch(
                agent_model="phi-4-mini",
                role=f"Cluster Specialist {index}",
                context=fork_context
            )
            parallel_results.append(agent_response)
            
        return parallel_results
